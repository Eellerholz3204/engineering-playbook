# Coding Standards

- Prefer clarity over cleverness.
- Deliver complete, production-quality implementations.
- Centralize configuration and path resolution.
- Validate reconstructed persisted records.
- Fail clearly and avoid silent partial success.
- Do not leak secrets through errors, logs, prompts, or generated artifacts.
- Keep dependencies pointing inward toward stable abstractions.
- Use domain language consistently across code, CLI, persistence, reports, workspaces, and documentation.
- Keep orchestration thin and domain behavior explicit.
- Operational scripts must be repeatable, validate prerequisites, support preview where practical, and avoid destructive defaults.
